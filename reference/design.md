# ออกแบบจากความต้องการ: หน้าตาของ dashboard มาจาก brief

ทุก dashboard ใช้ชุดดีไซน์เดียวกัน (`design/ui.css`) จึงดูแลง่ายและมีคุณภาพเท่ากัน แต่**หน้าตาของแต่ละงานต้องมาจาก brief ของงานนั้น**
จอทีวีในห้องทีม, หน้าที่ผู้บริหารลูกค้าเปิดบนมือถือ และหน้าที่ฝังในแอปเดิม ต้องออกมาไม่เหมือนกัน
งานจะเสร็จเมื่อทุกตัวเลือกในบรรทัด "ตัดสินใจแล้ว" มีเหตุผลที่ชี้กลับไปที่ brief ได้

## 1. design brief (เขียนไว้ที่หัวไฟล์ ก่อนแตะโค้ด)

| ข้อ | ถามว่า | ตัวอย่างคำตอบ |
|---|---|---|
| คนดู / ดูจากไหน | ใครเปิด เป็นคนของทีมหรือของลูกค้า บนจออะไร ระยะเท่าไร | หัวหน้าทีมบนโน้ตบุ๊ก · ทีวี 55" ห่าง 3 เมตร · CEO ลูกค้าบนมือถือ · iframe ในแอปเดิม |
| ดูนานแค่ไหน เพื่อตัดสินใจอะไร | เหลือบ 5 วินาที, เช็กทุกเช้า 1 นาที หรือนั่งไล่หาสาเหตุ | "มีบอทไหนล่ม ต้องลุกไปดูไหม" · "เดือนนี้จะถึงเป้าไหม" |
| ต้องเห็นก่อนอย่างอื่น | **อย่างเดียว** ที่ต้องเด่นที่สุด | คำตัดสินว่าปกติ/ผิดปกติ · ยอดเทียบเป้า · งานที่เกินกำหนด |
| อารมณ์ / แบรนด์ | CI ของลูกค้า หรือคำบอกอารมณ์ 2–3 คำ | ทางการ พรีเมียม · สงบ เทคนิค · เป็นกันเอง สดใส |
| เนื้อหามีกี่ส่วน อะไรต้องกดดูต่อ | นับ section และสิ่งที่ต้องเปิดอ่านต่อ | 3 ส่วน ไม่มีอะไรต้องกด · 6 ส่วน มี dialog รายละเอียด |

ถ้าข้อไหนตอบจากคำขอและโค้ดไม่ได้ ให้ถาม user เฉพาะข้อนั้น (โดยเฉพาะ "ดูจากไหน" กับ "ต้องเห็นก่อน")
คนดูที่ไม่ได้ทำงานกับแถวข้อมูล (ผู้บริหาร, จอทีวี, ลูกค้า) **ไม่ต้องมี**ตัวกรองช่วงทั้งหน้า ตารางรายการ ปุ่มส่งออก ปุ่มรีเฟรช หรือคำว่า "ผู้ดูแลระบบ" ให้ตัดออกตั้งแต่ brief

## 2. จาก brief ไปเป็นตัวเลือกของหน้า

ตั้งที่ `<html data-shell data-hero data-density data-cards>` และ token รูปทรง แต่ละแถวคือจุดเริ่ม ถ้า brief บอกต่างไปให้ทำตาม brief

| brief แบบนี้ | shell | hero | density | cards | รูปทรง |
|---|---|---|---|---|---|
| ใช้ทุกวันบนจอคอม เนื้อหา 5 ส่วนขึ้นไป | `side` | `banner` | comfortable | raised | soft |
| ผู้บริหาร/ลูกค้า เนื้อหาไม่เกิน 4 ส่วน | `single` (ไม่มีเมนู) หรือ `top` | `plain` | comfortable | outline | crisp |
| จอทีวีเปิดค้าง ไม่มีคนกด | `wall` | `plain` | comfortable (wall ขยายตัวอักษรให้เอง) | flat | crisp หรือ sharp |
| ฝังในแอปหรือเว็บเดิม | `embed` | – | ตามแอปเดิม | outline | ตามแอปเดิม |
| ไล่งาน/หาสาเหตุ ของบนจอเยอะ | `side` หรือ `top` | `plain` | compact | outline | crisp |
| หน้าให้ลูกค้าดู เน้นแบรนด์ | `side` หรือ `top` | `banner` + `--banner-img` ของลูกค้า | comfortable | raised | ตามรูปทรงโลโก้ |
| พนักงานเปิดบนมือถือเป็นหลัก | `top` | `plain` | compact | flat | soft |

- **shell:** `side` = แถบเมนูข้าง (เนื้อหาหลายส่วน ต้องกระโดดไปมา) · `top` = แถบเมนูบน ได้พื้นที่กว้าง · `single` = ไม่มีเมนู มีแบนเนอร์ (หน้าเดียวที่เลื่อนอ่านต่อกัน, ลบ `<aside>` ทิ้งได้, ตั้ง `--page-max` จำกัดความกว้าง) · `wall` = ไม่มีเมนูและปุ่ม ซ่อนทุกอย่างที่มีคลาส `wall-hide` · `embed` = ไม่มีแถบและแบนเนอร์ พื้นโปร่ง
- **hero:** `banner` = แสงฟุ้ง แถบเฉียง ภาพแบรนด์ · `plain` = ชื่อหน้าอย่างเดียว เรียบ
- **cards:** `raised` = มีเงา · `outline` = เส้นขอบไม่มีเงา (ทางการ, พรีเมียม, พิมพ์) · `flat` = พื้นสีอ่อนไม่มีขอบ (จอมืด, ทีวี, มือถือ)
- **รูปทรง** (token `--r-card / --r-inner / --r-ctl`): soft = `22px / 16px / 999px` · crisp = `12px / 10px / 10px` · sharp = `6px / 4px / 6px` เลือกให้เข้ากับโลโก้และอารมณ์ (โลโก้มน → soft, การเงิน/ราชการ/พรีเมียม → crisp, ห้องควบคุม → sharp)

ลองตัวเลือกอื่นได้โดยไม่แก้ไฟล์: `index.html?shell=top&hero=plain&density=compact&cards=outline&theme=dark`

### จอทีวี (`wall`)
- `ui.js` ทำให้เอง: ออกแบบที่ 1920×1080 แล้วย่อ/ขยายทั้งหน้าตามจอ (720p และ 4K หน้าตาเดียวกัน), ซ่อนเคอร์เซอร์, กันจอดับ (ต้อง HTTPS), โหลดหน้าใหม่ทุก 6 ชม. เมื่อเซิร์ฟเวอร์ตอบ
- ใส่ `data-theme="dark"` ที่ `<html>` (จอทีวีตั้งธีมเองไม่ได้ ห้องสว่างให้ใช้ `?theme=light`)
- ทั้งหน้าต้องอยู่ในจอโดยไม่ต้องเลื่อน ถ้าไม่พอ ให้ตัดเนื้อหา อย่าย่อตัวอักษร (ชุดดีไซน์ตั้งตัวอักษรเล็กสุด 20px ที่ 1080p ไว้แล้ว ห้ามตั้งเล็กกว่านี้)
- จำนวนการ์ดเปลี่ยนได้ (บอท 6 ตัววันนี้ 9 ตัวพรุ่งนี้) ให้วางแผนไว้ว่ามี 7–8 และ 9–12 ตัวแล้วจะตัดบรรทัดรองตัวไหนออก (ไม่ใช่ย่อตัวอักษร) และเทสต์ด้วยข้อมูลจำนวนนั้น `page_check.py --fit` จับได้ทั้งหน้าที่ต้องเลื่อนและเนื้อหาที่ล้นการ์ดลงล่าง
- การ์ดของแต่ละตัว (ระบบ, บอท, สาขา) **อยู่ตำแหน่งเดิมเสมอ** ไม่เรียงใหม่ตามความรุนแรง คนดูจำได้ว่าตัวไหนอยู่ตรงไหน
- ตัวที่มีปัญหาเปลี่ยนสีทั้งใบ (`statCard` state `crit`/`warn`) ส่วนตัวที่ปกติเงียบไว้ จากไกล ๆ ต้องเห็นก้อนสีแดงก่อนอ่านออก
- ความสดของข้อมูลสำคัญที่สุด: ใช้ `UI.live` ข้อมูลค้างแล้วตัวเลขจะจางเป็นเทา มีแถบแดงบอกเวลา และคำสรุป "ปกติ" ต้องซ่อน (`st.stale`) จอที่ค้างแล้วยังเขียวทั้งจอคือความผิดพลาดที่อันตรายที่สุด
  - เวลาของข้อมูลมาจาก `generated_at` ในข้อมูล หรือ header `X-Generated-At` / `Last-Modified` (`UI.dataTime` อ่านให้) ถ้า API เดิมส่งแค่ array ไม่มีเวลา ให้เสนอ `{ generated_at, items: [...] }` เป็นข้อเสนอที่ต้องยืนยัน ถ้าเป็นไฟล์ที่ cron เขียน nginx ส่ง `Last-Modified` ให้เองอยู่แล้ว
  - ข้อมูลที่อัปเดตวันละครั้ง (ยอดขายเมื่อคืน) ตั้ง `staleSec` ตามรอบนั้น (เช่น 30 ชม.) ไม่ใช่ 3 นาที

### ผู้บริหาร / ลูกค้า
- คำถามมักผูกกับ "เดือนนี้" จึงไม่มีตัวกรองช่วงทั้งหน้า ถ้ากราฟต้องเลือกช่วง ให้วางปุ่มไว้ในการ์ดกราฟนั้น
- ยอดเทียบเป้าต้องมีขีดบอกว่า "ควรถึงตรงไหนแล้ว" (`meter` + `mark: UI.monthPace().pct`) ไม่งั้น 42% กลางเดือนจะดูน่าตกใจ
- เทียบกับ "ช่วงวันเดียวกัน" ของเดือนก่อน (`UI.monthPace().prevSame`) และเขียนตัวเลขเงินเป็น "ล้าน" (`UI.fmtMillion`)

## 3. สีและฟอนต์

**สี:** ใช้แหล่งแรกที่มี
1. CI ของลูกค้า (คู่มือ, CSS ของเว็บไซต์, โลโก้) ตาม `branding.md`
2. design system ของทีม (เครื่องมือภายใน) ตาม `branding.md`
3. ไม่มีทั้งสองอย่าง: เลือกสูตรอารมณ์ด้านล่าง แล้วรัน `ui-ux-pro-max` แบบ `--design-system` ด้วยคำบอกชนิดงานกับอารมณ์ (`--density 8` สำหรับงานปฏิบัติการ, คำว่า `kiosk signage` สำหรับจอทีวี) เพื่อเอา palette และคู่ฟอนต์มาใช้

- ฟอนต์หัวเรื่องและตัวเลขใหญ่ตั้งที่ `--font-display` เนื้อหาตั้งที่ `--font` และแก้ `<link>` Google Fonts ให้ตรง ใช้ไม่เกินสองตระกูล
- ตั้ง token ครบทั้ง 3 ชุด (`:root`, dark ใน media, `[data-theme="dark"]`) โหมดมืดต้องเลือกสีใหม่จากสีแบรนด์ ไม่ใช่กลับสี
- รัน `python3 design/check_tokens.py <ไฟล์>` ต้องขึ้น "ผ่านทุกคู่" (ตัวหนังสือทุกชนิดบนพื้นของมันทั้งสองโหมด และชุดมืดสองชุดต้องตรงกัน)
- สีของกลุ่มข้อมูล (`--s1..`) ตรวจด้วยตัวตรวจ palette ของสกิล dataviz · สีสถานะ (ok/warn/crit) ใช้กับสถานะเท่านั้น มีไอคอนกับคำกำกับเสมอ และสีเน้นของแบรนด์ต้องไม่ซ้ำกับสีเตือน

### สูตรอารมณ์ (จุดเริ่ม แล้วแทนสีด้วย CI)

สูตรคือชุดของ "ตัวเลือก + token ที่ต่างจากค่าเริ่มต้น + หลักที่ทำให้หน้าออกมาเป็นอารมณ์นั้น" ใส่ token ใน `:root` ของหน้า

**ทางการ พรีเมียม** (ผู้บริหาร, ลูกค้าระดับบน, รายงานประจำเดือน)
```
<html data-shell="single" data-hero="plain" data-cards="outline">
--r-card: 14px; --r-inner: 10px; --r-ctl: 10px; --r-pill: 8px; --shadow: none; --shadow-sm: none;
--w-head: 500; --w-num: 400; --num: <สีหลักของแบรนด์>; --ref: <สีเน้น เช่น ทอง>; --ref-ink: <สีเน้นโทนเข้มที่ผ่าน 4.5:1>;
--page: <ขาวอุ่น/งาช้าง>; --line: <เส้นบางโทนอุ่น>; --page-max: 1240px;
ฟอนต์: หัวเรื่อง Noto Serif Thai หรือ Kanit + เนื้อหา Sarabun/Noto Sans Thai
```
- ตัวเลขสำคัญใหญ่แต่**น้ำหนักบาง** (400) สีแบรนด์ ใช้ `.bigstat` แทนการ์ดไอคอนวงกลม และหัวการ์ด**ไม่มีไอคอน** (ไม่ใส่ `icon` ใน LAYOUT)
- สีเน้นใช้น้อย: เส้นเป้า, ขีดบอกจังหวะ, ตัวเลขอันดับ · พื้นที่ว่างเยอะ การ์ดน้อยแต่กว้าง (`w: 7 + 5`)
- ไม่มีแสงฟุ้ง แถบเฉียง เงา หรือ gradient

**ห้องควบคุม จอมืด** (จอทีวี, บอร์ดสถานะ)
```
<html data-shell="wall" data-hero="plain" data-cards="flat" data-theme="dark">
--r-card: 10px; --r-inner: 8px; --r-pill: 8px; --w-num: 700;
--page: <เทาเกือบดำ>; --surface: <เทาเข้ม>; --crit-fill / --crit-on / --warn-fill / --warn-on: สีทึบของการ์ดที่มีปัญหา
ฟอนต์: Bai Jamjuree หรือ IBM Plex Sans Thai
```
- ปกติ = เงียบ (สีพื้นเดียวกับการ์ด) · มีปัญหา = สีทึบทั้งใบ · คำสรุปบนสุดบอก**ชื่อ**ตัวที่มีปัญหา ไม่ใช่แค่จำนวน
- ตัวเลขหลักหนึ่งตัวต่อการ์ด ใหญ่ที่สุดในการ์ด ตัวเลขรองเรียงข้าง ๆ และไม่มีอะไรต้องกด

**เป็นกันเอง ค้าปลีก** (ทีมขาย, หน้าร้าน, ลูกค้าทั่วไป)
```
<html data-shell="top" data-hero="banner" data-cards="raised">
--r-card: 22px; --r-inner: 16px; --r-ctl: 999px; --w-head: 600;
--page: <ครีม>; --primary: <ดินเผา/ปะการัง>; --accent: <เขียวหม่น>; --banner-img: <รูปสินค้า/ร้าน>
ฟอนต์: หัวเรื่อง Mitr + เนื้อหา Prompt
```
- การ์ดไอคอนวงกลม, แบนเนอร์มีรูปของแบรนด์, สีอุ่น · ยังใช้สีแดงกับปัญหาเท่านั้น

**เทคนิค ทีมปฏิบัติการ** (เครื่องมือภายใน ใช้ทุกวัน — ค่าเริ่มต้นของ page.html ใกล้สูตรนี้)
```
<html data-shell="side" data-hero="banner" data-density="compact|comfortable" data-cards="raised">
token ของ design system ทีม (teal) ตาม branding.md · ฟอนต์ Anuphan
```
- ของบนจอเยอะได้ (compact) แต่ทุกการ์ดยังต้องตอบคำถามใน brief

## 4. วางองค์ประกอบ

- **สิ่งที่ "ต้องเห็นก่อน" อยู่บนสุด และใหญ่หรือกว้างที่สุดในหน้า** มีได้อย่างเดียว ถ้าทุกอย่างเด่นเท่ากัน ก็ไม่มีอะไรเด่น
- เรียง section บนลงล่างตามคำถามใน brief (ด่วนไปถึงละเอียด) แต่ละ section ตอบคำถามได้หนึ่งข้อ section ที่ตอบไม่ได้ให้ตัดทิ้ง
- จัดด้วย `.flow` (ตาราง 12 ช่อง): ใส่ `w` ใน `LAYOUT` ให้ความกว้างบอกความสำคัญ เช่น กราฟหลัก `w: 8` คู่กับตัวเลขเทียบเป้า `w: 4` หรือ `7 + 5` ไม่จำเป็นต้องแบ่งครึ่งเท่ากันทุกแถว
- การ์ดตัวเลข (`.tiles`) มีได้ 2–4 ใบ ส่วนตัวเลขรองให้ใส่ใน hint
- ระยะห่างใช้ค่าของชุดดีไซน์ (16px, ถ้า compact ใช้ 12px) ห้ามตั้ง margin เองทีละการ์ด

## 5. แบบของ section (เลือกตามคำถาม ไม่ต้องใช้ครบ)

| คำถามของคนดู | ชิ้นส่วน (`design/ui.js` + `ui.css`) |
|---|---|
| ตัวเลขสรุป 2–4 ตัว ปกติไหม | `UI.tile({ icon, label, value, hint, status })` ใน `.tiles` (`--n` = จำนวนใบ) |
| ทุกตัวปกติไหม (คำตัดสินรวม) | `.chips` ของ `UI.pill(tone, 'ล่ม 1')` บนสุด ซ่อนเมื่อ `st.stale` |
| ระบบ/สาขา/บอทแต่ละตัวเป็นอย่างไร | `UI.statCard({ name, state, stateText, nums, meter, foot })` ใน `.grid` (`--min` = ความกว้างต่ำสุด) · state ที่ไม่รู้จัก = `'unknown'` |
| ตัวเลขเดียวที่สำคัญมาก เทียบกับก่อนหน้า/เป้า | `.bigstat` + `UI.delta(cur, prev, { goodWhen })` + `UI.sparkline(values)` + `UI.meter({ mode: 'target', mark })` |
| ใกล้เต็มหรือยัง (ดิสก์, โควตา) | `UI.meter({ label, pct })` (ส้มที่ 80%, แดงที่ 100%, มีคำกำกับ) |
| เปลี่ยนไปอย่างไรตามเวลา | `UI.barChart(el, { points, unit, ref, axisFmt })` (ช่วงที่ยังไม่จบ `dim: true`) |
| สะสมแล้วเทียบเป้า/เดือนก่อน | `UI.lineChart(el, { labels, series: [{ values }, { values, dashed: true }], area: true })` |
| ใครหรืออะไรมากที่สุด (และโตไหม) | `UI.rankList([{ label, value, prev }])` (มี `prev` = มีป้ายการเปลี่ยนแปลงในแถวเดียวกัน) |
| มีเหตุการณ์หรืองานอะไรต้องทำ | `.lrows` > `.lrow` + `UI.pill(tone, text)` + `UI.rel(time)` |
| รายการจริงทีละแถว | `<div class="tablewrap"><table>` (ถ้าต้องกรองช่วง/ค้นหา/ส่งออก ใช้ทาง ENGINE) |
| อ่านรายละเอียดทั้งชิ้น | `<dialog class="dlg">` (`.d-head` + `.d-body`) |
| ข้อมูลสดไหม | `UI.live({ load, render, every, at })` (page.html ทำให้แล้ว) |

- ข้อมูลเป็นแถว CSV: `UI.getCSV(url)` แล้วรวมเองด้วย `UI.between` (ช่วงเวลา), `UI.sum`, `UI.groupSum` (ตามสาขา/ช่องทาง), `UI.dayKey`/`UI.weekKey` (รายวัน/รายสัปดาห์ เวลาไทย) และ `UI.monthPace()` (ต้นเดือน, จุดเดียวกันของเดือนก่อน) · เกินประมาณ 20,000 แถวหรือ 5 MB ให้หลังบ้านรวมมาเป็น JSON แทน
- เงิน: `UI.fmtMillion(n, { digits: 2, always: true })` ให้ทุกแถวในรายการเดียวกันเป็นหน่วยและทศนิยมเดียวกัน
- ต้องการชิ้นที่ไม่มีในตาราง ให้เขียน CSS เฉพาะหน้าใน `[แก้ 4]` โดยใช้ token (`var(--...)`) เท่านั้น ถ้าชิ้นนั้นใช้ซ้ำได้ ให้เพิ่มใน `design/ui.css` ของสกิล แล้วรัน `python3 design/sync.py`
- ไอคอนเป็น SVG ของ Lucide ใน `UI.ICONS` ถ้าต้องการตัวที่ไม่มี ให้เพิ่ม path ของ Lucide ห้ามใช้ emoji

## 6. ตรวจก่อนส่ง

1. รัน `tests/test_page.py` (เทสต์ตั้งต้นของทาง 2) และ `tests/page_check.py --out` ที่ขนาดจอจริงของ brief ทั้งสองธีม แล้วเปิดภาพดูเอง ถามตัวเองว่า**ใน 5 วินาทีแรก เห็นสิ่งที่ "ต้องเห็นก่อน" หรือไม่**
   - โน้ตบุ๊ก/มือถือ: `--sizes 390x844,1440x900` · จอทีวี: `--sizes 1280x720,1920x1080,3840x2160 --schemes dark --fit` · ข้อมูลมีวันที่ตายตัว: `--now 2026-10-14T15:05:00+07:00`
2. บรรทัด "ตัดสินใจแล้ว" ในหัวไฟล์ต้องไม่ใช่ค่าเริ่มต้นของ page.html ทั้งหมด (side · banner · comfortable · raised · soft · Prompt · สี placeholder) อย่างน้อยสีและฟอนต์ต้องมาจาก CI หรืออารมณ์ ส่วนตัวเลือกที่ตรงกับค่าเริ่มต้น ต้องมีเหตุผลจาก brief กำกับ
3. ข้อมูลตัวอย่างของ page.html ต้องไม่เหลือ: `grep -nE "demo\(|ร้านค้าออนไลน์|เสื้อยืดคอกลม" <ไฟล์>` ต้องไม่เจอ
4. `check_tokens.py` ผ่าน และลองให้ endpoint ล่มหรือส่ง `generated_at` เก่า แล้วดูว่าหน้าบอกความจริง (แถบแจ้ง + ตัวเลขจาง + คำสรุปหาย)
5. สถานะว่าง / โหลดไม่ได้ / ข้อมูลเก่า ต้องดูตั้งใจออกแบบ (บอกว่าเกิดอะไรและเป็นข้อมูลของเวลาไหน) ไม่ใช่การ์ดว่าง
