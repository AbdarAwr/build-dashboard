# preset chatbot: ข้อมูล log ของแชทบอท

ถ้ามี `local/chatbot-data-team.md` (ข้อมูลของบอทแต่ละตัวในเครื่องนี้ ไม่อยู่ใน git) ให้อ่านคู่กับไฟล์นี้

## ต้นทางข้อมูล
บอทเขียน log ลงฐานข้อมูล → api ของบอท (`/logs`) → reverse proxy ส่งต่อเป็น `/api/logs.csv` (หรือ `.json`) หลัง login gate

| แบบ | url ใน CONFIG | format | หมายเหตุ |
|---|---|---|---|
| ค่าเริ่มต้นของ preset | `/api/logs.csv?limit=50000` | csv | |
| api ที่ส่ง JSON | `/api/logs.json` | json | ต้องส่ง `images_data` มาด้วย ไม่งั้นรูปของคำตอบใหม่จะหายเงียบ ๆ |

คอลัมน์: `timestamp` (ISO มีโซนเวลา), `execution_id`, `session`, `question`, `answer` (markdown), `sources` (คั่นด้วย "; "), `images` (จำนวน), `images_data` (JSON `[{url, ref, doc_url}]`), `sources_data` (JSON `[{label, url, kind}]`), `email` (ถ้าบอทเก็บอีเมล)

## กติกาที่ต้องเหมือนกันทุกบอท
- **session จริงคือ UUID เท่านั้น** (`keep: r => isUUID(r.session)`) เพราะ widget สร้าง UUID v4 ส่วน session ที่ไม่ใช่ UUID (ชื่อที่ใช้ทดสอบหรือประเมินผล) เป็นแถวทดสอบ ต้องใช้ตัวกรองตัวนี้ตัวเดียวทั้ง KPI, กราฟ, ตาราง และหน้าประวัติ ตัวเลขสองหน้าจึงตรงกัน
- **marker**
  - `GATE_*` คือแถวที่ตอบโดยไม่ผ่าน agent เช่น GREETING, THANKS, OFFTOPIC, GARBLED, BACKFILL และ CAPPED (คำถามเกินโควตาต่อคน ซึ่ง widget ส่งต่อเจ้าหน้าที่) แถวเหล่านี้**ไม่นับโควตาหรือสถิติคำถาม** แต่ยังอยู่ในตารางพร้อมป้าย
  - `SALES_CARD` คือบอทส่งต่อเจ้าหน้าที่
  - `EMPTY_LLM_RESPONSE` คือโมเดลตอบว่าง
  - `sources_data[].kind` มีค่า `gate`, `sales`, `error` และ `page`
- **กลุ่มคุณภาพคำตอบ** มี 5 กลุ่มไม่ซ้อนกัน ตัดสินตามลำดับนี้: สคริปต์ (GATE_* ยกเว้น CAPPED) > ส่งต่อ (SALES_CARD หรือ CAPPED) > มีรูป > มีที่มา > อื่นๆ (ไม่มีที่มา/ตอบว่าง) ถ้าบอทไม่มีการส่งต่อ ให้ลบ `sales` ออกจาก `order` และ `GROUP`
- **โควตา** นับตามเดือนปฏิทิน เวลาไทย เริ่มใหม่วันที่ 1 ไม่นับ GATE_* และไม่ขึ้นกับช่วงที่เลือก ค่า `QUOTA_MONTH` ให้ถาม user หรือดูจากสัญญา ถ้าลูกค้าไม่มีเพดาน ให้ตั้ง `QUOTA_MONTH = 0` การ์ดจะกลายเป็น "คำถามเดือนนี้" ที่ไม่มีหลอดและไม่มีการแจ้งเตือน
- **รูป** อยู่ที่ `/crops/` บนเครื่องเดียวกัน แต่ log เก่าอาจเก็บ URL ของโดเมนเดิมไว้ `IMG_HOSTS` จึงต้องมี**ทุกโดเมนที่บอทเคยใช้** (ทั้งโดเมนที่เลิกใช้แล้วและโดเมนปัจจุบัน) แถวเก่าบางแถวยังเก็บรูปเป็น `![ref](url)` ในคำตอบ ซึ่ง preset นี้รองรับแล้ว
- **เวลา** ทุกจุดแสดงเป็นเวลาไทยและปี พ.ศ. (ENGINE จัดการให้แล้ว ห้ามเปลี่ยนไปใช้ `toLocaleString` หรือโซนเวลาของเครื่อง)

## คีย์เวิร์ด (การ์ด "คีย์เวิร์ดที่ถามประจำ")
ใช้ whitelist `[ชื่อที่แสดง, [คำที่นับ...]]` ห้ามใช้ตัวตัดคำ เพราะจะได้เศษคำอย่าง "วอ", "เตอ", "รู้"
1. ห้ามดึงคำถามดิบลงเครื่อง (PII) ให้เลือกอย่างใดอย่างหนึ่ง: (ก) รันสคริปต์บนเครื่องจริง คืนเฉพาะคำหรือวลีที่พบบ่อยพร้อมจำนวน หรือ (ข) ให้ user ส่งตัวอย่างคำถามที่ลบข้อมูลส่วนตัวแล้ว จากนั้นจัดหมวดตามโดเมนลูกค้า ให้แต่ละหมวดมีคำพ้องทั้งไทยและอังกฤษ
2. ใส่คำยาวไว้ก่อน (engine จับคำยาวก่อนแล้วตัดทิ้ง) คำไทยสั้นที่ชนคำอื่นให้ใช้ RegExp เช่น `/ฝา(?![ก-ฮ])/` เพื่อให้ฝา ≠ ฝาก และ `/ใส(?![่้])/` เพื่อให้ใส ≠ ใส่
3. แถว `[null, [...]]` ใช้กินคำทั่วไปที่มีในทุกคำถาม เช่นชื่อบริษัท หรือ "สวัสดี" ทิ้งไป
4. เป้าคือครอบคลุมคำถามจริง 85% ขึ้นไป วัดด้วยสคริปต์บนเครื่องจริงที่คืนแค่เปอร์เซ็นต์ แล้วใส่คู่คำถามตัวอย่าง (แต่งขึ้นเอง) กับหมวดที่คาดไว้ใน fixture ให้เทสต์ตรวจ
5. ถ้า user สั่งเอาหมวดไหนออก ให้เปลี่ยนชื่อหมวดนั้นเป็น `null` และห้ามใส่กลับมาอีก

## หลังบ้าน (login gate)
- reverse proxy: `/dashboard/`, `/logs/`, `/api/logs.csv` และโฟลเดอร์ไฟล์ที่ลูกค้าอัปโหลด ต้องผ่านการตรวจ login ถ้าไม่ผ่านให้ 302 ไป `/login/?next=…`
- เปิดสาธารณะ: `/login/`, `/assets/`, `/crops/`, `POST /auth/login`, `GET /auth/logout`
- สัญญาของหน้า login: ฟอร์ม `username`, `password`, `next` ถ้าถูกให้ตั้ง cookie HttpOnly แล้ว 302 ไป next ถ้าผิดให้ 302 ไป `/login/?e=1&next=…`
- `logs.html` คือหน้าส่งต่อไป `/dashboard/#logs` ให้ deploy ไว้ที่ `/logs/` เดิม เพื่อไม่ให้บุ๊กมาร์กเก่าเสีย

## บั๊กฝั่งเซิร์ฟเวอร์ที่รู้แล้ว
- endpoint `/logs` ที่เขียน `ORDER BY ts ASC LIMIT n` จะ**ทิ้งแถวใหม่สุด**เมื่อข้อมูลเกิน n ให้แก้เป็นเรียงจากใหม่ไปเก่าก่อนตัด แล้วค่อยกลับลำดับ หรือเพิ่ม limit ฝั่งหน้าจะขึ้นคำเตือนเมื่อ `RAW_COUNT >= data.limit` แต่แก้ปัญหาให้ไม่ได้
- คอลัมน์เวลาในฐานข้อมูลต้องเก็บโซนเวลา (เช่น `timestamptz` ของ PostgreSQL) ถ้าไม่มีโซน เวลาจะเพี้ยนไป 7 ชั่วโมง

## ส่วนเสริมเฉพาะบางบอท (พอร์ตเฉพาะฟังก์ชันมาเขียนเป็นโค้ดใน CONFIG เฉพาะเมื่อบอทนั้นมีฟีเจอร์นี้ ห้ามก็อปมาทั้งไฟล์)
- รูปที่ลูกค้าแนบมา (image-input: คอลัมน์ `image_file`, `image_text` และโฟลเดอร์ไฟล์อัปโหลด) ให้เขียน render เพิ่มใน `turnEl`
- อีเมลที่ลูกค้ากรอก preset นี้รองรับคอลัมน์ `email` อยู่แล้ว
